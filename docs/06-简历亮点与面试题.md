## 一、项目一句话

> "OpsMind 是一个面向单兵运维的『定时巡检 + AI 智能分析 + 对话助手』平台：定时在目标机跑巡检脚本，采集结构化结果，AI 自动产出带证据链的分析报告；提供知识库 RAG 对话助手与三层记忆；异常时自动触发黑板契约的多 Agent 协作诊断（Planner→Executor→Reviewer，已实现最小版）。"

## 二、核心亮点（STAR 式，每个 2~4 句背）

### 亮点 1 · 判定体系：确定性第一关 + 单 LLM 第二关（report_type × level 双轨）
- **问题**：巡检结果"跑没跑成"和"有多严重"是两件事，混在一起会导致渲染/触发失控。
- **设计**：第一关确定性短路（exit≠0/超时/主机不可达→error，永远不走 LLM）；通过且有有效输出才进第二关，LLM 读原始输出+规则文本→`{level, reason}`。`report_type` 决定渲染模板与 AI 介入方式，`level` 决定严重度颜色/计数/是否触发深度诊断，二者正交。
- **效果**：判定零超卖（不会把 error 判成 ok）、LLM 只在真异常走、判断可审计。

### 亮点 2 · 报告分析 = 异步流水线 + read_run_output 磁盘存档
- **问题**：报告生成慢，100 个 run 串行要很久；且把大段原始输出直接喂 LLM 会爆 token。
- **设计**：报告异步流水线——②意图表格确定性毫秒先出推给用户，③ LLM 分析并行但受"LLM 全局限流器(信号量+令牌桶)"约束；脚本原始输出完整落磁盘，只把"概况+文件位置"给 LLM，按需经 `read_run_output(keyword/区间)` 精读。
- **效果**：用户先看到表格、③渐进补齐、异常批次诊断联动触发（`batch_ready` 先出表格，`diag_*` 事件随后、`done` 收尾）；LLM 输入可控，不丢关键行。

### 亮点 3 · 知识库"内容侧优先"：结构化单元 + 多 key + RRF + 位置必须对
- **问题**：短查询 vs 长文档块语义失配，召回不准；LLM 引用位置不可信。
- **设计**：文档规范化为"value 原文保真 + 多 key 标签(LLM 生成)"；检索=向量+BM25 经 RRF 融合→候选(topK=6)带 parent_context 给 LLM 选；每个 key_index 指回原文偏移，"答案可以偏、位置必须对"，引用经 O4 校验管线核实。
- **效果**：召回命中率可量化验证（评估体系），引用可复核，防断章取义。

### 亮点 4 · 三层记忆 + compact 上下文压缩
- **问题**：LLM 无状态，长会话/跨会话经验留不住；上下文超限会爆。
- **设计**：Working=当前会话（compact 压缩：系统+摘要+最近N轮+本轮）；Episodic=片段闭合沉淀历史事件；Semantic=LLM 提炼长期经验规律(pgvector+90天半衰期)。预算=ctx−max_output−reserved，80% 触发，usage 校准账本。
- **效果**：越用越懂系统、经验跨会话可复用、成本可控不爆窗口。

### 亮点 5 · 异常联动诊断（多 Agent 协作：Planner→Executor→Reviewer）〔已实现·最小版〕
- **问题**：单个 LLM 直接猜根因会幻觉。
- **设计**：crit/error 才触发——Planner 拆假设(≤6)，三个只读 Executor（日志/指标/变更）用**只读探针**并行查真实数据写黑板各自格子，Reviewer 汇总证据出"结论+置信度+证据引用"。所有采集走 D38 闭环（`run_script` 只读幂等重试、失败降级透明）。
- **实现**：真用 LangGraph `StateGraph`（`START→planner→{exec_log,exec_metric,exec_change}并行→reviewer→END`）；黑板契约 `DiagnosticState`（各写各格 + `validate_contract` 保证"无证据不出结论"）；LLM 只在 Planner/Reviewer、Executor 用确定性采集；幂等落 `TaskRun.diagnosis_json`、`diag_started/diagnostic_done/diag_failed` SSE、总超时+并发上限。
- **效果**：结论基于真实采集数据而非脑补、只花 2 类 LLM 调用（Planner+Reviewer）、证据可复核。
- **诚实边界**：最小版尚不含"时间对齐的复杂交叉验证"、无独立前端页（用 `GET /task-runs/{id}/diagnosis` 查）。

### 亮点 6 · AI 助手（运维 Copilot）〔已实现〕
- **问题**：运维知识散、需要"边问边查"的入口。
- **设计**：SSE 流式对话（`start/kb_ready/token/done`）+ 知识库 RAG（勾选才查、RRF、引用带来源）+ 会话/消息持久化（CRUD/改名/软删/分页）+ 一键保存为 Episodic 记忆 + 输出敏感打码 + 工具调用审计；LLM 失败自动降级回显检索结果。
- **效果**：回答有依据、可溯源，失败不空白（降级仍有内容）。

### 亮点 7 · 报告校验管线（O4）〔已实现〕
- **问题**：LLM 输出可能"一本正经胡说"，且引用不可信。
- **设计**：零 LLM 五阶段确定性校验（结构/证据/矛盾/越界/等级一致）；柔性标注（只标不删）+ 批次横幅 + 规则可配（`pipeline_config`）；"答案可以偏、位置必须对"。
- **效果**：缺证据强制存疑、引用必须真实存在；AI 内容可复核，不盲信。

## 三、高频追问攻防（面试问答备）

### 判定/报告
- **"两关模型是什么？"** → 第一关确定性短路(exit≠0/超时/主机不可达直接 error，不走 LLM)；第二关 LLM 读结果+规则文本判 ok/warn/crit。阈值比较在单 LLM 模式已废弃，等级由 LLM 判（含义可控、可审计）。
- **"report_type 和 level 区别？"** → report_type 由执行确定性判、管渲染模板/AI介入；level 由 LLM 判、管严重度颜色/计数/是否触发深度诊断。二者正交（一个 success 可以有 ok/warn/crit）。
- **"报告怎么异步？"** → ②表格确定性毫秒先出（`batch_ready`）；③ LLM 分析并行受全局限流器；异常批次的诊断在同一执行任务内联动触发——`diag_*` 事件后于 run 结果、先于 `done`，前端可在同一 SSE 通道顺序渲染；"报告完成"=①②+批次视图+③尽力。

### 多 Agent / 黑板〔已实现最小版，可用代码回答〕
- **"为什么 Executor 不用 LLM？"** → 它们的活是"照假设调只读探针查数据写黑板格子"，确定性即够，用 LLM 反而慢贵不稳；LLM 只用在要推理的 Planner/Reviewer。
- **"黑板契约是什么？"** → 共享状态(schema)约束：每个 Agent 只写自己格子(`evidence_logs/metrics/changes`)，只读他人，Reviewer 汇总。LangGraph 里即 `StateGraph(DiagnosticState)` 的状态契约；`flags/degradation_notes` 用 `Annotated[list, reducer]` 支持并行合并。
- **"怎么保证不瞎下结论？"** → `validate_contract()`：三格证据全空时清空 `conclusions` 并标 `flags=["证据不足"]`；Reviewer LLM 失败降级为"仅按哪类证据非空"的低置信度规则结论，不无中生有。
- **"工具失败怎么办？"** → 采集层 `mcp_client` 对只读幂等调用做 3 次指数退避重试，失败**不写证据格**、只落 `degradation_notes`（透明）；诊断整体失败不落库、发 `diag_failed` 允许重试。

### 上下文/记忆
- **"上下文怎么压缩？"** → compact：系统提示恒定 + 旧轮→LLM摘要 + 最近N=10轮verbatim + 本轮；预算=ctx−max_output−reserved(10k或20%)；组装完本轮完整输入后判断，≥80%触发；摘要固定分区(目标/关键事实/已给结论/悬而未决)、增量压缩。
- **"token 怎么算准？"** → 字符估算起步，每轮回包读 usage.prompt_tokens 重锚定账本（误差只限一轮），流式必须 include_usage；能力表内置+前端可覆盖+溢出自动降档。
- **"三层记忆怎么协作？"** → Working=当前会话(压缩维护)；Episodic=历史事件片段(片段闭合触发，代码硬杀+LLM判断+代码收尾去重)；Semantic=长期经验规律(累计≥30提炼+跨会话证据校验+置信度衰减)。注入=query_memory 工具按需，不自动塞。

### 知识库
- **"为什么不能用全量检索？"** → 默认"勾选才查"，search_kb 只在勾选文档集内检索，全量=显式开关，防污染与 token 失控。
- **"为什么 key 打平存？"** → 一个 value 可被多个问法命中，key_index 打平行(key_text/vector/tsvector→unit_id)解决"多 key→同一 value"且不同部分 key 不混。
- **"RRF 为什么？"** → 向量分和 BM25 分不可比，只看排名融合(score=Σ1/(k+rank))，免调参、稳。

### 安全/部署
- **"部署在哪？"** → 控制端本机 + 目标机执行服务仅绑 localhost、经 SSH 隧道/Tailscale 连，公网零暴露；单用户自备 API key。
- **"怎么防注入？"** → 直接(用户输入)+间接(文档/工具返回不可信)都做：系统指令与检索内容物理分隔；输出侧生成文本都过一次敏感打码。
- **"限流为什么？"** → 所有 LLM 调用共用一个全局限流器(信号量+令牌桶)，防自家 Agent 死循环/依赖抖动，非防外部滥用（私网单用户无公网威胁）。
