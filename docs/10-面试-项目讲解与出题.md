## 一、自我介绍脚本

### 30 秒版
> "我最近做的个人项目叫 OpsMind，是一个面向单兵运维的「定时巡检 + AI 分析 + 对话助手」平台。它会定时在目标机上跑巡检脚本，采集结果，由 AI 自动产出**带证据链**的分析报告；还提供一个能查知识库、能落记忆的运维对话助手。技术上是 Python + FastAPI + LangGraph + pgvector + MCP，前后端分离、有单测和 CI。我做这个项目的重点是**AI 应用怎么做得可控、可评审、可信**。"

### 2 分钟版（加"为什么这么做"）
> "……（30 秒版）……我在设计上做了几个我认为比'调通一个 RAG'更重要的取舍：
> 第一，**判定拆成两关**——退出码/超时这类确定性信号绝不让 LLM 判，只有真跑出结果才让 LLM 判严重程度，这样既省 token 又不会误判；
> 第二，**报告是异步流水线**——结果表先出，AI 分析并行补，用户不用干等；
> 第三，**知识库坚持'位置必须对'**——检索单元是'原文保真 + 多个问题标签'，引用能点回原文，AI 答案可以偏但出处必须能核对；
> 第四，**AI 输出过确定性校验管线**（O4 五阶段），缺证据就标存疑；整条链路有全局限流器，失败会降级并透明说明。
> 另外异常诊断我**设计了**一个黑板契约驱动的多 Agent 协作（Planner→Executor→Reviewer），目前代码里还是设计预留。"

> 口径说明：**已实现** = 判定/报告/助手/校验管线/知识库/记忆/执行/MCP/鉴权/评估；**设计预留** = 黑板契约的多 Agent 深度诊断。面试别把后者说成"已实现"。

## 二、怎么用它（演示路径话术）

> 现场/线上演示按这个顺序走，边点边说。

1. **登录**：admin 密码 → JWT（`app/api/auth.py`）。"私网部署，仍是单账号鉴权。"
2. **加目标机**：填 MCP endpoint + 密钥 → 点探测（`ping`）。"加主机即验连通，通过才入库。"
3. **写脚本/用模板**：脚本库 CRUD + LLM 预览（试判）+ 跟踪指标。演示一条 `check-xxx`。
4. **建任务**：归属主机、勾脚本、设调度（间隔/cron）→ 立即执行。
5. **看报告（核心）**：②结果表先出 → ③AI 分析逐段出（SSE：`run_result/batch_ready/ai_done/done`）；③内容过 O4 校验，存疑处标注/横幅。
6. **知识库**：上传 md/pdf → 规范化单元预览 → 勾选文档后助手/分析可引用，点引用跳原文。
7. **AI 助手（重点演示）**：新建会话 → 不勾选文档时明确"未勾选、未检索"；勾选后再问 → SSE 流式回答（`start→kb_ready→token…→done`），回答带知识库来源 → "保存为记忆"落 Episodic；演示改名/删除/消息翻页。
8. **记忆**：Episodic/Semantic 两个 tab，可看/编辑/删除。
9. **评估**：故障案例集 → 运行 → 命中率/误报率/质量评分（雷达）。
10. **设置**：模型/API key（掩码）/默认文档集/技能开关。

**演示金句**："重点看两个地方——报告是**渐进出现**的（表→分析），以及每条 AI 结论都能**点回证据**；助手你不勾文档它就不检索，勾了才查。"

## 三、项目怎么实现的（结构 + 关键链路）

### 分层（对照 `backend/app/`）
```
api/       路由：auth hosts scripts tasks task_runs runs documents memory chat eval settings stats
services/  业务：judgment(两关) report(报告) execution(执行引擎) validation(O4)
           scheduler/task_scheduler(调度) context(上下文压缩) evaluation audit events metrics
core/      db / llm / limiter(限流熔断) logging / exceptions
executor/  目标机 FastMCP 服务 + 控制端 MCP client
graph/     助手对话编排（LangGraph）
knowledge/ normalizer splitter keygen indexer search(RRF)
memory/    episodic semantic core
models/    ORM（会话/任务/run/report/文档/unit/key_index/记忆/settings）
```

### 关键链路 1 · 一次巡检执行（`services/execution.py`）
```
触发 → TaskRun(RUNNING)
  → 逐脚本 MCP 下发 run_script(content,params,timeout)
  → 原始输出落磁盘 outputs/{tr}/{run}.out（R-1）
  → 第一关 first_gate()：exit/超时/可达/空 → report_type（不走 LLM）
  → 若 success → 第二关 second_gate_llm() → {level,reason,metrics}（过限流器）
  → 落 Run + Report 占位 → SSE 推 run_result（表格边跑边亮）
  → 全部完成 → 批次汇总 batch_ready → done
```

### 关键链路 2 · 判定两关（`services/judgment.py`）
- 第一关 `first_gate`：`timeout/host_unreachable/error/empty` 四类短路，返回 `report_type` + 是否进第二关；
- 第二关 `second_gate_llm`：拼"背景 + 规则 + 原始输出(截断)"→ 要求模型只输出 `{"level":"ok|warn|crit","reason","metrics"}`；失败抛 `JudgmentFailure` → 上层降级 `unknown` 不阻塞。

### 关键链路 3 · 知识库（`knowledge/`）
- `normalizer` 把 md/txt/pdf 规范化为带 `<!-- UNIT -->` 的 md；`splitter/keygen` 抽单元 + 生成多 key；
- `indexer` 把 key 打入 `key_index`（embedding + tsvector）；`search.hybrid_search` = 向量 + 中文 jieba→BM25 → `rrf_fuse` → topK 候选（带 parent_context）；
- 默认"勾选才查"：`if not doc_ids and not allow_full_library: return []`。

### 关键链路 4 · 上下文压缩（`services/context.py`）
- `budget_of`：预算 = ctx − max_output − reserved（reserved=min(10000, ctx×20%)）；
- `should_trigger`：估算 ≥ 预算×80%；`generate_summary` 用轻模型按固定分区压缩；`_estimate_tokens` 中英分档粗估（回包用 usage 校准）。

### 关键链路 5 · 限流/熔断（`core/limiter.py`）
- 全局单例 `limiter`：信号量（并发）+ 令牌桶（RPM）+ 三个熔断器（llm/tool/kb，连续失败 OPEN→半开→恢复）；所有 LLM/工具调用统一经办。

### 关键链路 6 · AI 助手对话（`api/chat.py` + `api/chat_sessions.py`）
```
POST /chat(body: message, document_ids, session_id?)
  → 落 session/user 消息
  → 工具循环：search_kb（_bind_retriever；未勾选文档则返回"未检索"）
  → SSE: start → kb_ready{found} → token…（LLM astream，逐块 mask_sensitive）
  → 落 assistant 消息（含 tool_calls）+ 更新 last_active_at
  → SSE: done{reply, session_id}
  失败降级：LLM 异常/限流 → 回显检索结果（不空白）
会话：GET/POST /chat/sessions、PUT/DELETE、GET messages(分页 before_id)、POST save-memory
```

### 关键链路 7 · O4 校验管线（`services/validation.py`）
- `run_pipeline(ai_content, level, ...)`：P1 结构 / P2 证据 / P3 矛盾 / P4 越界 / P5 等级一致；
- 柔性标注（只标不删）+ `pipeline_config` 开关 + 汇总横幅；被报告与助手回答复用。

## 四、面试官视角题库（核心）

> 用法：每题给 **考察意图 → 答题框架 → （取舍）**。A=简历钩子，B=由回答追问，C=设计取舍。

### A · 从简历钩子直接出的题

**A1（判定）："两关模型具体怎么分？阈值去哪了？"**
- 考察：是否真懂"确定性 vs 模型判断"的边界。
- 答：第一关确定性——退出码≠0/超时/主机不可达/空输出，直接定 `report_type`，**永不调 LLM**；第二关才 LLM 读"原始输出+规则文本"判 `{level, reason}`。阈值比较在早期设计里砍掉了（单 LLM 模式），等级交给 LLM 是为了灵活处理自由文本，代价是不确定性 → 用 O4 校验与"建议复核"兜。
- 取舍（C 延伸）："为什么不干脆全让 LLM 判？"——确定性能算的不要交给模型，省 token、可审计、不会把'脚本没跑成'误判成'业务正常'。

**A2（报告）："100 个脚本的报告怎么不慢？"**
- 答：报告是异步流水线——②结果说明是确定性的、毫秒级先推给用户；③分析并行跑，但**所有 LLM 调用都过全局限流器**（信号量+令牌桶），瓶颈是 API 限额而非线程数；cirt/error 的深度诊断异步回填，不阻塞"报告完成"。
- 取舍："为什么不上无限线程池？"——瓶颈在模型 API 的并发/速率上限，开再多线程也是排队；用信号量+令牌桶才是对的。

**A3（知识库）："为什么用 RRF，不全用向量？"**
- 答：向量擅长语义但漏精确词（错误码、命令）；BM25 擅长精确词但不懂近义。RRF 只用**排名**融合（score=Σ1/(k+rank)），不用纠结余弦分和 BM25 分量纲不可比，免调参、稳；topK 候选再交 LLM 按问题裁决。
- 取舍："为什么不用 rerank 模型？"——单用户先省成本，rerank 留作演进点。

**A4（记忆）："记忆会不会越记越乱？"**
- 答：Episodic 走"代码硬杀（空/寒暄丢）→ 候选召回 → LLM 判同主题 → 代码收尾合并"；Semantic 必须**累计≥30 且跨≥2 会话、evidence 真实**才从史实提炼规律，无规律不写；前端可整体/分层开关 + 逐条删改。

**A5（MCP）："执行服务怎么不是'远控木马'？"**
- 答：四层——执行服务**只绑内网/localhost**、经 SSH 隧道连接（公网零暴露）；双向凭据握手；**解释器白名单 + 危险命令拦截 + 超时 + 非 root**；全量审计。控制端统一托管脚本、每次下发内容，目标机不落盘脚本。

**A6（助手）："你的对话助手能干嘛？怎么保证不瞎答？"**
- 答：SSE 流式对话 + 知识库 RAG（**勾选才查**，RRF 混合检索、带来源）+ 会话/消息持久化（CRUD/改名/软删/分页）+ 一键保存为 Episodic 记忆 + 输出敏感打码 + 工具审计。不瞎答靠三点：①不勾文档就明确"未检索"，绝不硬编；②回答基于检索到的真实片段并带来源；③LLM 失败/限流时**降级回显检索结果**，不返回空。
- 取舍："为什么 SSE 流式？"——对话是长输出，流式让用户先看到、并能在中途判断要不要打断。

**A7（校验管线）："O4 校验管线拦什么？为什么用代码不用 LLM？"**
- 答：五阶段零 LLM——P1 结构（该有的字段在不在）、P2 证据（结论有没有引用，无引用标存疑）、P3 矛盾（证据打架标冲突）、P4 越界（引用 run/doc 是否存在）、P5 等级一致（判 warn/crit 但输出无异常迹象→提示复核）。用代码是因为它是**确定性规则**、零成本、可解释；LLM 复核反而不稳。缺证据不删内容，只"柔性标注 + 横幅"。

### B · 从回答里顺势追问

**B1："你说 LLM 判定不确定，那你怎么保证它判得对？"** → O4 校验管线五阶段（结构/证据/矛盾/越界/等级一致），零 LLM、只标注不删；缺证据强制"存疑"，出口打码、横幅提示人工复核。
**B2："工具调用失败怎么办？"** → 脚本执行层：`mcp_client` 对只读幂等调用做 **3 次指数退避重试（1s/2s/4s）**，仍失败则落 `degradation_notes` 并在报告透明展示（已实现）。更完整的 LLM 工具闭环（入参自纠≤2、三档降级）是**设计**（异常类与审计钩子已就位）。
**B3："上下文怎么不爆？"** → compact：系统+摘要+最近 10 轮+本轮；预算公式 + 80% 触发；摘要固定分区 + 增量；回包用 `usage.prompt_tokens` 重新校准估算。
**B4："记忆怎么注入？每轮都塞吗？"** → 不。用 `query_memory` 工具**按需**调用（渐进式），和知识库一样是"用得上才查"，避免污染上下文。

### C · 设计取舍题（"为什么这么设计而不是 XXX"）

| 问题 | 答题要点（结论 + 为什么 + 代价） |
|---|---|
| 为什么判定拆两关，不一个 LLM 全包 | 确定性信号不该交给模型；省 token、可审计、防误判；代价是两套逻辑要维护 |
| 报告为什么异步，不一次生成完再返回 | 用户体验（表先出）+ 限流友好；代价是 SSE 事件与前端状态机更复杂 |
| 知识库为什么"勾选才查"，不默认全库 | 防检索噪音/幻觉、控 token、可控范围；代价是用户要多一步勾选 |
| 为什么用 pgvector，不单独上 Milvus/Chroma | 单机 2C4G + 元数据与向量要一起查（join），一体省运维；代价是超大规模时不如专用库 |
| 为什么自研限流器/熔断，不用框架 | 单机单实例，需求就是"并发上限+速率+熔断"三件事，自己写更可控；代价是功能不如 Sentinel 全 |
| 为什么执行走 MCP，不直接 SSH 跑命令 | 协议标准化、可换实现、天然可被 AI 当工具；代价是多一层服务 |
| 为什么上下文用 compact，不用纯截断 | 截断会丢早期目标/结论；摘要保关键、增量更新；代价是压缩要花一次轻模型调用 |

## 五、难点→思路→取舍→效果（把亮点讲成"故事"）

| 难点 | 思路 | 关键取舍 | 效果 |
|---|---|---|---|
| 判定又要灵活又要稳 | 两关模型 | 确定性优先、LLM 兜语义 | 省 token、无误判、可审计 |
| 报告慢/LLM 打爆 API | 异步流水线 + 全局限流器 | 瓶颈在 API 限额不在线程 | 表格先出、③并行、诊断异步 |
| 短查询 vs 长文档块 | 结构化单元 + RRF | 位置必须对、勾选才查 | 召回准、引用可核 |
| 长会话/跨会话经验 | 三层记忆 + compact | 按需注入、摘要保关键 | 越用越准、不爆窗口 |
| 知识散、要边问边查 | AI 助手（SSE + RAG） | 勾选才查、失败降级 | 有依据、可溯源 |
| AI 输出可能瞎说 | O4 校验管线（零 LLM） | 只标注不删、缺证据存疑 | 可复核、不盲信 |
| 单 LLM 猜根因会幻觉〔设计预留〕 | 多 Agent 协作（黑板） | Executor 用确定性代码 | 目标：结论基于真实数据 |

## 六、面试收尾（反问/引导）

- 主动说一句："这个项目我最想聊的是**'AI 应用怎么做得可信'**——包括两关判定、O4 校验、降级透明。"
- 若被问"和真正生产级 AIOps 差距"：坦白——单机规模、无多租户、无海量日志平台；强项是**架构取舍与工程闭环**。
