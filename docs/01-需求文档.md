# OpsMind · 智能运维诊断平台 · 需求文档

> 版本：v0.2（与决策日志 D1–D48 对齐，TBD 已清理）

---

## 一、产品定位

**一句话**：面向单兵运维/中小团队的**定时巡检与智能分析平台**——定时执行巡检脚本 → 采集结构化结果 → AI 自动产出带证据链的分析报告；异常时触发深度诊断，知识库辅助问答。

**不是**：AI 凭空写报告（浅）、SSH 命令执行器（不安全）、ELK 替代（日志平台）。

---

## 二、目标用户

- **运维工程师 / 值班人员（主打）**：中小企业、单兵运维，没有专职 SRE 团队，告警多、人手少、经验分散。
- **运维负责人 / TL（辅助）**：沉淀团队处置经验、规范排查流程。

## 四、用户角色与操作流程

### 4.1 角色

**单用户（控制端本机部署）**。不设多用户，系统所有配置与数据归一人所有；admin 密码登录 + JWT 会话校验（D48）。

### 4.2 核心流程

**巡检流程**：
1. 添加主机（填写 MCP endpoint + 认证密钥 + 主机描述）
2. 编写/导入脚本（或使用内置模板），配置 AI 规则文本（LLM 判定规则）
3. 创建巡检任务（归属该主机，关联脚本，设定调度周期）
4. 任务自动按周期执行，或手动立即执行
5. 执行结果经过两关判定（第一关确定性短路+第二关 LLM 判定）→ 生成报告（4 类渲染模板，SSE 实时推流）
6. 异常项触发 AI 深析 → 确定性校验管线标注入报告
7. 报告可查看/归档/历史趋势

**AI 助手流程**：
1. 在设置页配置模型（供应商/API key/模型/temperature）和默认文档集
2. 进入对话界面，选择 Skill/工具/知识库范围
3. 输入问题，AI 按配置引用知识库、调用工具、生成回答
4. 回答可切换模型重新生成

## 五、非功能需求

### 5.1 性能（设计目标，待压测验证）

| 指标 | 目标值 | 说明 |
|---|---|---|
| 单脚本执行 P50 | < 2s（含 MCP 下发+远端执行+回传） | 目标机同局域网 |
| 全批报告生成 P95 | < 30s（10 脚本×1 主机） | 含 ③AI 分析 |
| LLM 深析 P95 | < 8s（单异常项） | 通义千问 API 为主 |
| 确定性判定 P50 | < 200ms | 不走 LLM |
| 知识库检索 P50 | < 100ms | pgvector HNSW 索引 |
| 并发执行 | 5 个脚本同时跑 | 信号量控制 |

### 5.2 可用性

| 指标 | 目标值 |
|---|---|
| 服务可用性（单机） | 99.9% |
| 调度不掉线 | 任务持久化 PG jobstore，重启恢复 |
| 执行失败 | 有限重试 + 失败记录 + 可审计 |

### 5.3 安全

| 要求 | 设计 |
|---|---|
| 执行通道安全 | 网络隔离(仅内网/localhost) + 双向凭据(HMAC) + 白名单+黑名单+受限账号+超时 |
| LLM 调用 | 前端配置 API key / 加密存 PG / 明文不回传 |
| 用户输入 | 输入注入检测（直接+间接文档注入）（D39） |
| 输出 | 敏感信息过滤/打码（所有生成文本出口）（D48） |
| 限流 | 全局限流器（ND 信号量+令牌桶）覆盖所有 LLM 调用（D47） |

### 5.4 部署环境

| 项 | 说明 |
|---|---|
| 控制端 | 本机（开发/演示） |
| 被管主机 | 可配置多台，云/本机；执行服务仅绑 localhost/内网 |
| 通道 | SSH 隧道 / Tailscale（公网零暴露） |
| 云服务器 | 2C4G，TicketGo + 被管主机双角色 |

## 六、功能边界与范围外

| 不在此项目范围 | 说明 |
|---|---|
| 不提供任意 SSH 命令执行 | 只执行控制端下发脚本（白名单） |
| 不自动执行危险命令 | 处置建议只读（D13） |
| 不提供完整日志平台 | 轻量定向检索，非 ELK |
| 不提供自定义 Skill 框架 | 演进点 |
| 不提供多用户/团队协作 | 单用户 |
| 不提供告警引擎 | 由巡检结果驱动，而非外部告警接入 |
