## 版本 A：粘贴用（较完整，约 8~10 行）

**OpsMind · 智能运维诊断平台（个人项目）** 　2026.09 – 至今
`Python` `FastAPI` `LangGraph` `PostgreSQL/pgvector` `MCP` `APScheduler` `SQLAlchemy` `Vue3` `Docker` `pytest`

- 面向单兵运维的「定时巡检 + AI 分析 + 运维对话助手」平台：定时在目标机执行巡检脚本，采集结构化结果，AI 自动产出带证据链的分析报告；提供知识库 RAG 对话助手与三层记忆。自研后端 40+ 模块、30 个单测、GitHub Actions CI。
- **判定体系（两关模型）**：第一关确定性短路（退出码/超时/可达性/空输出）永远不走 LLM，第二关才由 LLM 读"原始输出+规则文本"判 `ok/warn/crit`；`report_type`（渲染/AI 介入）与 `level`（严重度）正交，避免误判与无效 LLM 调用。
- **报告异步流水线**：②结果说明确定性毫秒先出，③ LLM 分析并行且**经自研全局限流器**（信号量+令牌桶+熔断）约束；脚本原始输出落磁盘、LLM 经 `read_run_output` 按需精读，避免超长上下文。
- **AI 助手（运维 Copilot）**：SSE 流式对话（`start/kb_ready/token/done`）+ 实时知识库 RAG（勾选才查、RRF 混合检索、引用可溯源）；会话/消息持久化（CRUD/改名/软删/分页）；**LLM 失败自动降级回显检索结果**；一键保存为 Episodic 记忆；输出敏感打码 + 工具调用审计。
- **报告校验管线（O4）**：零 LLM 五阶段确定性校验（结构/证据/矛盾/越界/等级一致），柔性标注 + 横幅 + 规则可配，**防 AI 幻觉、保证结论可溯源**（"答案可以偏、位置必须对"）。
- **知识库 RAG**：文档规范化成"原文保真 + 多 key"结构单元，向量 + 中文 BM25 经 **RRF 融合**召回、topK 候选交 LLM 裁决；默认"勾选才查"。
- **三层记忆 + 上下文压缩**：Working（compact 压缩：系统+摘要+最近N轮）/ Episodic（片段闭合沉淀）/ Semantic（LLM 提炼长期规律 + 置信度衰减）；预算=窗口−输出−预留，按用量校准。
- **MCP 执行通道**：目标机 FastMCP 暴露 `ping/run_script/get_runtime_info`，控制端经 SSH 隧道连接，解释器白名单 + 危险命令拦截 + 超时 + 审计，做到"只跑登记脚本"的最小权限闭环。

> 诚实口径说明：**已实现** = 判定/报告/助手/校验管线/知识库/记忆/执行/MCP/鉴权/评估；**设计预留（未编码）** = 黑板契约驱动的多 Agent 深度诊断（Planner→并行 Executor→Reviewer），代码仅留设置项与 SSE 事件占位。面试统一按此口径说，不夸大为"已实现"。

## 写法建议（给简历排版）

1. **一条亮点一行**，行首动词（设计/实现/自研/落地），行内可加粗关键名词。
2. **不写"精通/深入"**，写"设计/实现/取舍"更稳——面试官才敢顺着问。
3. **数字诚实**：本项目暂无线上压测，别写"QPS 提升了 X 倍"；写"架构按可扩展设计、目标单机 X"。
4. **与另一项目分工**：本项目的价值是"AI 应用工程化 + 后端工程素养"，别硬吹成高并发项目。
