## 二、模块职责

### 2.1 控制端模块

| 模块 | 职责 |
|---|---|
| **主机管理** | Host CRUD；MCP 连通性探测；存储连接参数与认证信息 |
| **脚本库** | 脚本 CRUD（内置模板+自定义）；版本/标签/参数/启停；LLM 规则文本配置 |
| ~~指标库~~ | **已废弃**（D36 单 LLM 模式替代） |
| **任务调度** | 任务 CRUD + 模板方案库；APScheduler 管理定时/立即执行 |
| **执行引擎** | 下发脚本到目标机 MCP 执行服务；回收结果；重试；超时控制 |
| **判定引擎** | **单 LLM 模式**：LLM 读原始结果+规则文本→输出 `{level, reason, metrics?}`；两关模型（第一关确定性短路+第二关 LLM 判定） |
| **报告中心** | **5 类渲染模板**（success/error/timeout/empty/host_unreachable）；头部元信息行+主体区按类型切换；SSE 实时推流 + 异常批次联动诊断推送 | 详细设§2 |
| **AI 分析** | 基于执行结果的异常深析（4 类：AI 分析 / AI 失败诊断 / 固定文案 / 空输出提示） | 详细设§1 |
| **确定性校验管线** | O4 五阶段零 LLM 校验；标注存疑/冲突/越界 |
| **异常联动诊断** | 异常触发 Planner→并行 Executor→Reviewer 多 Agent 管线（LangGraph `StateGraph` + 黑板契约状态共享）；D51 已实现最小版 |
| **趋势** | 跟踪指标定义（脚本级，LLM+正则兜底）→ 数值折线图（生效区间+断点如实）→ AI 趋势小结（按需点击） |
| **工具注册表+黑板** | ToolRegistry（工具登记+入参/出参 schema 校验+安全级别）；黑板契约（多 Agent 状态即 State schema 约束）；工具闭环（自纠重试/自动重试/降级三档/降级透明化） |
| **AI 助手** | 对话/问答；Skill 执行；知识库检索；工具调用 |
| **知识库** | 文档上传→分块→向量化→检索；引用定位 |
| **三层记忆** | Working（会话摘要+最近N轮）、Episodic（历史事件片段）、Semantic（长期经验规律） | 详细设§7 记忆/评估/安全 |
| **历史会话管理** | session CRUD(改名/删除/列表)+message 存储(完整原文)+summary 存档摘要；per-session 串行锁；清理=30天归档+软上限300；降级=内存会话+提示 | 详细设§6 知识库与助手 |
| **评估体系** | 故障案例集管理、评分运行、报告生成 | 详细设§7 记忆/评估/安全 |
| **设置管理** | 模型配置/文档集/Skill/MCP 连接/API key 加密存储 |
| **AI 安全** | 注入检测/敏感过滤/限流熔断 |

### 2.2 目标机模块

| 组件 | 职责 |
|---|---|
| **FastMCP 执行服务** | 暴露 3 个 MCP 工具；接收控制端下发脚本并执行；回传结果 |
| **安全守护** | 受限账号运行；黑名单拦截；超时管控；审计日志 |

## 三、技术栈

| 层次 | 技术 |
|---|---|
| 后端框架 | Python 3.11+ · FastAPI · Uvicorn |
| Agent 框架 | LangGraph · LangChain |
| LLM | 通义千问(DashScope) · 兼容 OpenAI 接口（可切换 DeepSeek/Qwen 等） |
| 向量库 | **pgvector**（PostgreSQL 一体存储：文档元数据+向量+记忆+会话） |
| 执行协议 | **MCP**（Model Context Protocol，FastMCP Server） |
| 调度器 | APScheduler（内嵌，PG jobstore 持久化） |
| 数据库 | PostgreSQL（业务+向量一体） |
| 缓存 | Redis（可选） |
| 前端 | Vue3 + Vite（轻量） |
| 测试 | pytest · pytest-asyncio · pytest-cov |
| 部署 | Docker Compose（本机）；SSH 隧道连接目标机 |

## 四、部署拓扑

```
┌── 本机（控制端） ───────────────────────────────────┐
│  OpsMind 控制端(FastAPI+PG+Redis+LLM)              │
│  Docker Compose 或 原生运行                         │
│  SSH 隧道 Local port → 远程服务器 localhost:8003    │
└──────────────────────┬──────────────────────────────┘
                       │ SSH Tunnel / Tailscale
┌── 云服务器(2C4G) ────┴──────────────────────────────┐
│  FastMCP 执行服务 (仅绑 localhost:8003)              │
│  TicketGo（可选，作为巡检对象）                      │
└─────────────────────────────────────────────────────┘
```

- 公网**不暴露**任何端口
- 远程访问 Web 用 Tailscale（免费、加密、零配置）
- 与 TicketGo 项目共用同一台云服务器（TicketGo=被管主机双角色）

## 五、数据流（一次完整执行）

```
用户点「立即执行」（任务: check-all, 主机: host-01, 脚本: cpu/disk/mysql）
  ↓
① 控制端创建 TaskRun（状态: RUNNING）
  ↓
② 对每个脚本→MCP Client 调 run_script(script_id, content, params, timeout)
  ↓ SSH 隧道
③ 目标机 FastMCP 执行服务：受限账号跑脚本 → 回传 {exit_code, stdout, stderr, duration}
  ↓
④ 控制端第一关判定
   ├─ exit≠0 / 超时 / 环境失败 → error（不走 LLM，按 report_type 处理）
   └─ exit=0 且输出为空 → unknown（不走 LLM）
      exit=0 且有输出 → 进入第二关：LLM 读原始结果+规则文本 → {level, reason, metrics?}
  ↓
⑤ 按 report_type（success/error/timeout/empty）生成报告 → SSE 推给前端（用户立即看到）
  ↓
⑥ 异常项（warn/crit/error）→ 逐项触发 AI 深析
   深析结果 → O4 确定性校验管线 → 标注存疑/冲突 → SSE 推流
  ↓
⑦ 异常项（可选）→ 触发异常联动诊断（Planner→并行Executor→Reviewer）
  ↓
⑧ TaskRun 完成（状态: DONE）；报告可查看/归档
```

## 六、前端导航结构

```
仪表盘
├─ 主机 → 主机列表 → 主机详情
│        ├─ 本机任务列表 → 点任务 → 历史列表 → 点历史 → 各脚本报告

├─ 脚本库 / 知识库 / 文档
├─ 历史报告（跨主机/脚本筛选，含趋势）
└─ 设置
   ├─ 模型配置（供应商/模型/api key/temperature）
   ├─ 知识库默认文档集
   ├─ Skill 开关
   ├─ 工具/MCP 连接管理
   └─ 巡检分析默认模型
```
