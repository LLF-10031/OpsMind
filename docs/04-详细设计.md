## §0 总览（判定与报告 v4 完整链路）

> 实现必读 D 清单：D36 · D45 · D47（判定/报告/三图/概念澄清）
> 横切关注点：背景包注入(D47) · 输出敏感过滤(D48) · LLM 全局限流器(D47) · 审计(D48)

### 0.1 端到端链路

```
[触发：定时 / 手动]
  1. 建 task_run(tr-…，状态 PENDING)
  2. RUNNING：逐脚本下发（并发≤5，受控）→ 目标机 FastMCP run_script
     ... execute {exit, stdout, stderr, duration}
  3. 每 run 完成 → report 占位即建 → ①原始+②元信息行 落库+SSE run_result
  4. 全部 run 完成 → tr=COLLECTED → 批次汇总视图（增量已推）
  5. 报告分析图（每 run）：ok→模板 · warn→③LLM分析 · crit/error→拉起联动 · timeout/empty→固定文案
  6. （若有 crit/error）异常联动诊断图（批次级一次）→ diag_started/diagnostic_done/diag_failed
  7. tr=DONE（①②+汇总+③尽力）
```

> **D51 实现口径**：诊断在批次执行任务内**联动触发**（`diagnose_task_run`）——`batch_ready`（报告表/批次视图）先推给用户，随后诊断事件先行、`done` 收尾；诊断受 `diagnostic_total_timeout` 总超时与并发信号量约束，失败发 `diag_failed` 且不落库（可重试）。

### 0.2 数据/状态机

| 对象 | 状态 |
|---|---|
| task_run | PENDING → RUNNING → COLLECTED → DONE / FAILED |
| run | SUCCESS/ERROR/TIMEOUT/EMPTY/HOST_UNREACHABLE（由 report_type 决定，非状态机） |
| report | 按 run 生成：`report_type` + `level` + `③` + annotations + banner |

### 0.3 三张图的关系

- **报告分析图**：每次巡检的主干，产出②/③；
- **异常联动诊断图**：crit/error 才拉起，批次级根因排查，结论回填（批次诊断块）；
- **助手对话图**：用户主动入口，独立，共享 报告/记忆/知识库/工具。

## §1 判定体系

> 实现必读 D 清单：D20(两关模型骨架) · D36(单 LLM 模式 v4) · D45(脚本类型/O4收官) · D47(report_type/level 澄清、P-B 合并)
> 横切关注点：背景包注入(D47) · 输出敏感过滤(D48) · LLM 全局限流器(D47)

### 1.1 两层判定（最终）

**第一关 · 确定性短路（永久不走 LLM）**

| 条件 | report_type | 说明 |
|---|---|---|
| `exit_code ≠ 0` | `error` | 脚本报错 |
| 超时 | `timeout` | 执行超时 kill |
| 目标机连不上/执行服务不可达（重试3次无响应） | `host_unreachable` | 主机级失败，非脚本问题 |
| `exit=0` 且输出为空 | `empty` | 不调 LLM，标 unknown |
| `exit=0` 且有效输出 | `success` | → 第二关 |

**第二关 · LLM 判定（仅 success 有效时）**
```
输入：原始结果(截断/磁盘引用) + 判定规则文本 + 背景包
输出：{level: ok|warn|crit, reason, metrics?: {...}}
```
- Level 仅 `ok/warn/crit`（严重度由 LLM 判）；
- `metrics` 可选：跟踪指标顺带提取（D37）；
- 受 LLM 全局限流器约束；输出经敏感过滤（D48）。

### 1.2 report_type 与 level（概念澄清，防混淆）

| 字段 | 谁判 | 用途 |
|---|---|---|
| `report_type` ∈ {success,error,timeout,empty,host_unreachable} | 第一关确定性 | 渲染模板 + AI 介入方式 |
| `level` ∈ {ok,warn,crit} | 第二关 LLM（仅 success） | 颜色/计数/是否触发深度诊断 |
| `reason` | 第二关 LLM | ② 元信息行"原因"栏（可展开） |

**正交**：success 的 run 可以有 ok/warn/crit；error/timeout/empty 不上 LLM、level=对应状态语义。

### 1.3 AI 介入矩阵（D36 + D47 修正）

| run 情形 | AI 动作 |
|---|---|
| success + ok | 模板"正常"（0 LLM） |
| success + warn | ③LLM 分析（巡检医学上下文包 + 本批概况） |
| success + crit | **不另跑③** → 走批次级异常联动诊断（P-B 合并），run ③=指向诊断结论摘要 |
| error（exit≠0） | **失败诊断**（读 stderr → 错误摘要/可能原因/修复建议），批次级联动并行 |
| timeout / host_unreachable | 固定文案"请检查网络/目标服务配置"，无 AI |
| success + 输出空 | unknown + "输出为空，请检查脚本"，无 AI |
| 无 LLM 配置兜底 | success 一律 level=unknown + banner "未配置 AI 模型"（仅数据不分析） |

### 1.4 背景包（判定/分析/诊断的上下文输入）

```
context_bundle =
  host 快照（get_runtime_info / host 表描述，task_run 启动时打包缓存）
  + 脚本定义与规则文本
  + 系统/服务背景（拓扑：本机跑啥、MySQL/Redis/Kafka）
  + 本批概况（同级 run 的 report_type/level 列表）
  + 历史（同脚本×同主机近 N 期，可选）
  + 记忆/知识库（可选，按需 tool 查）
```
- 信息缺失 → 降级提示 ("主机信息不可用，分析仅基于结果")；
- R-1 磁盘存档：输出完整存磁盘，LLM 只拿"概况+文件位置"，按需经 `read_run_output` 精读。

### 1.5 边界与异常

| 场景 | 行为 |
|---|---|
| report_type=success 但 level=unknown | 渲染走 success 模板，徽标灰 + 存疑标注 |
| LLM 判定超时/失败 | 降级：level 落 newest unknown，报告③模板兜底，degradation_notes 记录 |
| 工具失败（read_run_output/search_kb…） | 走 D38 工具闭环（自纠≤2/重试3退避/三档降级/透明） |

## §2 报告与 SSE

> 实现必读 D 清单：D18(接口形态/状态机) · D36(报告v4/report_type) · D37(趋势) · D45(O4收官) · D47(渲染分派/R-1~R-6/批次实时/完成定义)
> 横切关注点：输出敏感过滤(D48) · 审计(D48) · 背景包注入(D47) · LLM 全局限流器(D47)

### 2.1 报告结构（最终形态）

一份 **run 级 Report**（单脚本单报告），不是三块严格独立的"三区块"，而是**按 report_type 渲染的分派结构**：

| 区块 | 内容 | 谁生成 |
|---|---|---|
| 头部元信息行 | script/host/耗时/exit_code/**level 徽标**/可展开"原因"(reason) | 确定性代码 |
| 原始输出区 | 磁盘存档(`outputs/{task_run/run}.out`) 渲染，可折叠/翻页 | 文件读取 |
| 主体区 | 按 report_type 切换模板：③分析/失败诊断/固定文案/空输出提示 | 按 AI 介入矩阵 |
| 批次诊断块（批级一次） | 异常联动诊断结论（crit/error 时出现） | 联动诊断图（批次执行内触发） |

### 2.2 report_type → 渲染模板分派（前端只做映射，语义判断在后端）

| report_type | 模板 | 主体区 |
|---|---|---|
| success(ok) | 🟢 正常模板 | "正常"(模板，0 LLM) |
| success(warn) | 🟡 warn模板 | ③LLM 分析段落 |
| success(crit) | 🔴 crit模板 | **占位"深度诊断中"** → 引用批次级诊断块摘要 |
| error | ❌ 错误 | ③失败诊断（错误摘要/可能原因/修复建议） |
| timeout | ⏰ 超时 | 固定文案"请检查网络/目标服务配置" |
| host_unreachable | 🚫 主机不可达 | 固定文案（目标机不可达） |
| success(unknown，无 LLM) | ⚙️ unknown 模板 | 灰标 + banner"未配置 AI 模型，仅数据不分析" |

> 边界：report_type=success 但 level=unknown（有输出但 LLM 无法解读）→ 仍走 success 模板，仅徽标灰 + 存疑。

### 2.3 报告"完成"定义（防状态机混乱）

| 达成时点 | 含义 |
|---|---|
| ①+② 就绪 | run 级"已出报告主体"（用户可先看到） |
| ② 全 + 批次视图 | batch_ready（批次汇总） |
| ③ 尽力完成 | run 级 DONE（③失败→模板兜底+degradation_notes） |
| 诊断追加 | **批次执行内联动触发**（`batch_ready` 先出，`diag_*` 事件随后、`done` 收尾；D51） |

### 2.4 SSE 事件集（前端状态机按此驱动，按 run_id 幂等去重）

| 事件 | payload | 触发 |
|---|---|---|
| `run_result` | `{run_id, report_type, level, summary}` | 每个 run ②就绪 |
| `batch_ready` | `{summary_jaon}` | 批次视图就绪 |
| `ai_done` | `{run_id}` | ③分析就绪（warn/success | error 失败诊断） |
| `diag_started` | `{run_ids[]}` | 联动诊断开始 |
| `diagnostic_done` | `{run_ids[], conclusions}` | 联动诊断完成，回填批次诊断块 |
| `diag_failed` | `{run_ids[], reason}` | 联动失败（回退模板） |
| `done` | `{task_run_id}` | 报告主体完成 |
| `error` | `{message}` | 异常结束 |

### 2.5 批量并发与限流（D47 调整点#1）

- 报告分析异步流水线：② 毫秒先出；③ 并行（LLM 全局限流器，信号量≤5~10 + 令牌桶按 API 限额）；
- 队列优先级：**诊断 > ③分析 > 摘要/记忆**；
- 排队超时 → ③降级为模板 + 标"分析排队中"；
- 前端幂等：按 run_id 去重渲染（防断开重连重复）。

### 2.6 R-1 磁盘存档（read_run_output）

- 输出完整存磁盘，DB 只存 `output_path + size + 首 N 行预览`；
- ③分析/诊断持 `read_run_output(run_id, start?, end?, keyword?, limit=100)` 按需精读；
- 路径由后端解析、防穿越、白名单目录；清理与报告联动 + 磁盘配额（如≤2GB）。

### 2.7 趋势（D37）

- 跟踪指标：脚本级定义 `{name, extraction: llm+regex|regex, unit}`，生效区间、断点如实；
- AI 趋势小结：按需点击，LLM 读同脚本×同主机近 N 期（窗口细参详设时定）。

## §3 执行通道与部署

> 实现必读 D 清单：D13(执行模型/MCP) · D30(部署姿态/执行安全四层) · D31(部署拓扑) · D45(脚本类型)
> 横切关注点：审计(D48) · 输出敏感过滤(D48)

### 3.1 部署姿态（单机 + 私网 + 隧道）

```
本机（控制端核心）：
  OpsMind 控制端(FastAPI+PG+Redis(可选)+LLM)  ← 用户登录/配置入口
    · SSH 隧道：localhost:8003 → 远程目标机执行服务
    · Tailscale（可选，远程访问 Web）
云服务器(2C4G)：
  FastMCP 执行服务（仅绑 localhost/内网：8003）
  TicketGo（可选，作为巡检对象）
```
- 公网零暴露（网络隔离：执行服务不监听公网）；
- 远端访问：SSH 隧道 / Tailscale；
- admin 登录（D48）：JWT 会话校验，登录取 token。

### 3.2 MCP 执行服务（目标机）

- FastMCP Server，暴露 3 工具：`ping()` / `run_script(script_id, content, params, timeout)` / `get_runtime_info()`；
- 控制端经隧道连接（MCP client, langchain-mcp-adapters）；
- **每次下发脚本内容、目标机不落盘**（控制端统一托管脚本库）；
- 脚本类型：Shell(Bash) / Python3，解释器白名单（`/bin/bash`、`/usr/bin/python3`）；
- 执行语义：一次性快照执行（超时 kill）；参数注入（params_json）。

### 3.3 执行安全四层（D30）

| 层 | 手段 |
|---|---|
| 网络隔离 | 执行服务仅 localhost/内网，公网不暴露 |
| 双向凭据 | ping 探测 + 共享密钥/HMAC，无凭据拒绝 |
| 白名单最小权限 | 只跑控制端下发脚本 · 危险命令黑名单 · 非 root 受限账号 + 只读 sudo 白名单 · 超时 |
| 审计 | 每次执行落日志（调用方/脚本/参数/结果/时间） |

### 3.4 资源与配额

- 磁盘：`outputs/{task_run}/{run}.out` 存档，配额（如≤2GB）+ 与报告保留联动清理（D47 R-1）；
- 内存：模型能力/系数缓存内存（D43），不每轮查库。

### 3.5 线程并发（报告生成时）

- ② 表格：确定性、毫秒级（线程池/async 并行，不耗 LLM）；
- ③ 分析：并行但受 LLM 全局限流器（信号量+令牌桶）——瓶颈在 API 限额，不在线程；
- 队列：报告生成任务进异步队列，全局并发≤4；LLM 全局并发≤5~10（可配）。

## §4 校验管线

> 实现必读 D 清单：D23(5 阶段骨架) · D45(O4 收官四项) · D47(report_type/level 澄清、锚点)
> 横切关注点：level/report_type 概念澄清(D47) · 审计(D48)

### 4.1 位置与职责

- 校验管线 = **AI 生成内容（③分析 + reason + 诊断结论）进入报告前的确定性闸门**，零 LLM、只查不写；
- "答案可以偏，位置必须对"：引用锚点（run_id/文档/原文片段）必须真实存在，无法核实的标存疑，绝不当真展示。

### 4.2 5 阶段（final）

| 阶段 | 查什么 | 动作 |
|---|---|---|
| P1 结构 | ③ 必含 现象/证据/结论/建议 | 缺主体→补"未提供"占位 |
| P2 证据 | 每条结论挂 run_id/文档引用？ | 无引用→强制"存疑" |
| P3 矛盾 | 同批证据冲突？ | 标"冲突"+给两假设，不强行裁决 |
| P4 越界/幻觉 | 引用的数字/文档是否真实存在 | 修正或标"存疑+来源无效" |
| P5 等级一致 | LLM 判 warn/crit 但原始数据全 ok（反向同） | 降级或标"建议人工复核" |

### 4.3 处理策略（D45 收官）

- **柔性标注（O4a）**：发现问题只打标注、不删 AI 内容；
- **报告横幅**：批次层出现"N 处存疑/矛盾，建议人工复核"（O4b）；
- **覆盖范围（O4c）**：③分析段落 + LLM reason 一起校验；
- **标注清单（O4d）**：落库、报告中可展开（显示"为什么标存疑"）；
- **规则可配置（O4e）**：五阶段可开关、默认全开（settings.pipeline_config）。

### 4.4 锚点

- 引用锚点 = 检索产生的**真实单元 ID + 位置**（doc_id/section/原文偏移），LLM 只允许引用"返回过的单元"；
- 校验：锚点真实存在？在允许引用集内（search_kb 勾选约束，D48）？不符→标存疑/拦截。

### 4.5 边界

- crit/error run：③不另跑，走批次诊断；校验作用于诊断结论与 run 引用摘要。
- LLM 失败：③降级模板+degradation_notes；校验仍然执行（对模板内容无引用→标记"无引用"但有固定文案展示）。

## §5 调度与执行引擎

> 实现必读 D 清单：D13(执行模型/MCP) · D17(调度器/静默重试/输出规范) · D19(对象模型) · D30(执行安全四层) · D45(脚本类型/快照执行/参数)
> 横切关注点：审计(D48) · LLM 全局限流器(D47)

### 5.1 调度器（APScheduler）

- **选型**：APScheduler（内嵌单进程），任务存 PG jobstore，重启可恢复；
- 演进点：Celery / K8s CronJob（多机、量大）；
- 周期：间隔（每 N 分钟）+ cron 表达式（前端可视化组件生成）→ 统一 `{type: interval|cron, value}`。

### 5.2 对象模型（执行管线）

```
Host ─1:N─ Task（归属单主机）→ TaskRun（历史）→ Run（脚本×主机快照，历史不可变）→ Report(1:1)
Template（方案库，不绑主机）— 套用 → 生成绑定主机的 Task
单脚本测试模式 = 独立 Run（不挂 TaskRun）
```

### 5.3 一次执行（时序）

```
[触发] 定时/手动
  → 建 TaskRun(PENDING)
  → RUNNING：逐脚本内容下发(并发≤5) → 目标机 FastMCP run_script(content,params,timeout)
  → 每 run：第一关 → (success)第二关 LLM → 建 report → SSE run_result
  → 全部完成 → COLLECTED → 报告分析图(③并行) → DONE
```

### 5.4 静默重试（O1b）

- 失败先静默重试（仅只读幂等脚本，有限次数，指数退避）；
- 重试仍败 → 进报告 + 附每次重试证据；
- 目的：区分瞬时抖动与持续故障，避免误报。

### 5.5 输出规范化（O2a，演进到单 LLM 后）

- 内置脚本尽量输出 JSON 契约（metric/value/unit/status/message）；
- 自由脚本靠 exit_code + 关键词兜底；
- 单 LLM 模式下 LLM 直接读原始输出判定，JSON 主要服务跟踪指标/趋势（D37）。

### 5.6 并发与限流（D47）

- 脚本执行并发 ≤5（信号量）；
- 报告生成异步队列，全局并发 ≤4；LLM 限流器（信号量 ≤5~10 + 令牌桶）覆盖所有 LLM 调用（判定/②③/诊断/摘要/记忆）；
- 队列优先级：诊断 > ③分析 > 摘要/记忆；排队超时 → ③降级模板。

### 5.7 断点续跑（P-E）

- report 状态存 DB，重启后未完成③ 幂等续跑（已完成不重跑）；前端按 run_id 去重。

### 5.8 定时作业接线（task_scheduler）

- `services/task_scheduler.py`：把 `Task.schedule_json` 注册为 APScheduler 作业（job_id=`task:{id}`）；

## §6 知识库与助手

> 实现必读 D 清单：D21(知识库+助手配置) · D40(文档规范化) · D41(知识库 v1/RRF/key) · D42(助手配置原则) · D43(上下文压缩) · D44(记忆+持久化) · D46(默认工具) · D47(助手对话图) · D48(输出过滤/search_kb约束/审计)
> 横切关注点：输出敏感过滤(D48) · search_kb 勾选约束(D48) · 审计(D48) · LLM 限流器(D47)

### 6.1 文档规范化管线（原文 → 规范化 md → unit → key_index）

```
上传(md/txt/pdf)
  → 加载：md透传 / txt包装 / pdf抽文本层(扫描页降级标注, OCR=演进)
  → 分块补丁：图片→原位"图片#n 解析"+序号(可选多模态)；表格→md table
  → 结构化骨架：标题树不动，每 section 一次小LLM生成 intent 写 UNIT 注释
  → 薄校验 + 预览确认 → unit 入库
  → key_index 向量化(key 打平行)
```
- 产物 = 带结构 Markdown（`<!-- UNIT id kind intent -->` 注释，机器切分/人可读/前端可隐藏）；
- 位置优先原文：`unit.source = {original_file, original_range(跳原文), section_id(次级)}`；
- "已规范"接受 md+txt（txt 按 md 解析），pdf 拒绝+薄校验报错引导；
- 类型自动检测切法（标题树/错误码/步骤/无结构→LLM 结构化，位置降章节级）。

### 6.2 检索（RRF + 两级匹配 + search_kb 约束）

- 混合：向量(key embedding) + BM25(key tsvector) → **RRF 融合**（score=Σ1/(k+rank)，k=60）；
- 候选 topK=6（可配5~8）→ 候选带 parent_context/分数/来源 → **LLM 在候选内选**；
- 命中任一 key_index → 反查 unit 得 value+parent_context+original_range；
- **search_kb 默认只在"勾选文档集"内检索；全量检索=显式开关放行（D48）**；
- embedding=text-embedding-v3/1024；embedding 不可用降级 TF-IDF/关键词（声明级）。

### 6.3 助手对话图（LangGraph）

```
[用户消息] → 注入检测(直接注入)
  → n1 组装上下文（D43：系统提示+摘要+最近N+本轮）
  → n2 LLM 决策（技能渐进披露：清单→需时 skill 工具取正文）
  → n3 工具循环（ToolRegistry，D38 闭环：自纠≤2/重试3退避/三档降级/透明）
        · search_kb(勾选集) · query_memory · read_run_output · 平台只读 · get_time
        · trigger_task_run(=ask，需人工确认)
  → n4 生成回答（SSE 流式）+ 输出敏感过滤(D48) + 引用锚点(点开原文)
  → n5 校验（O4：结构/证据/越界/存疑）
  → n6 落库 session/message + 记忆片段闭合挂钩（D44 Episodic 入口）
  → n7 上下文记账（usage 校准）→ 需要压缩
```

### 6.4 上下文压缩（D43 终稿）

- 预算 = `max_context − max_output(本次) − reserved`；reserved=`min(10000, ctx×20%)`；
- 触发：组装完本轮完整输入后 ≥预算×80% 先压缩 / ≥预算 必须压缩；
- 结构：系统提示(恒定) + 摘要 + 最近N=10 + 本轮；压缩用独立轻模型；
- 摘要固定分区（目标/关键事实/已给结论含引用/悬而未决）+ 增量压缩；summary_cap=`clamp(预算×20%,800,4000)`；
- usage 校准：每往返读 usage.prompt_tokens，流式开 include_usage；
- 切模型重算预算；摘要 DB 真源 + 内存 LRU。

### 6.5 记忆（三层，D44）

- **Working**：D43 上下文压缩维护的当前会话；
- **Episodic**：片段闭合（压缩/闲置10min/手动保存按钮）→ 去杂去重（代码硬杀+LLM判断+代码收尾）→ 入库（keywords[] 不向量化）；
- **Semantic**：累计≥30 且新增≥2 → 轻模型提炼 → 代码硬校验（证据真实/数量/跨会话）→ 置信度 90 天半衰期；前端记忆管理（开关+CRUD）；
- 注入：query_memory 工具按需，不自动塞。

### 6.6 历史会话持久化（D44）

- session(元数据/自动标题/可改名/软删) + message(完整原文/引用/usage) + summary(DB真源+内存LRU)；
- 打开会话只拉"摘要+最近N"；per-session 串行锁；清理=30天归档 + 软上限300。

### 6.7 降级（存储层，D44）

| 挂了 | 助手行为 |
|---|---|
| PG 业务库 | 内存会话（不落盘）+ 无RAG + 提示"历史未保存" |
| pgvector | 会话缓存检索(retrieval) + 提示"知识库不可用·缓存非实时" |
| 两者 | 最弱（内存+无检索）但可聊 |
| 探活恢复 | 自动回归持久化，降级期不补录、明示 |

### 6.8 文档在线浏览（G3）

- `GET /documents/{id}/content` 返回 `raw_content`（原文全文）+ `normalized_md`（规范化全文），均不截断；
- `GET /documents/{id}` 详情不再截断（此前 `[:8000]`）；
- 前端：Documents 页"读全文"（原文/规范化双页签）；Assistant 页侧栏"知识库"标签可直接浏览文档全文。

### 6.9 三组 AI 能力配置（G1）

- 设置页分三组：对话/分析（`llm_*`）· 文档处理/轻任务（`light_model`/`docproc_*`）· 向量 embedding（`embedding_*`）；
- 空 key/base_url 自动回落对话组；每个 `*_api_key` 加密存 PG、掩码不回传；掩码占位不覆盖；即时生效无需重启。

### 7.1 三层记忆实现（D44 细化）

| 层 | 写入 | 读出 | 存储 |
|---|---|---|---|
| Working | D43 压缩维护（会话轮） | 每轮组装上下文 | session/message/summary(DB真源+内存LRU) |
| Episodic | 片段闭合（压缩/闲置10min/手动保存）→ 去杂去重（代码硬杀+LLM判断+代码收尾） | query_memory 按需 | 表（keywords[] 不向量化，GIN） |

### 7.2 评估体系（O7，D48 落点）

- **触发**：离线独立、前端"评估"入口发起（非三图运行时）；
- **流程**：注入"已知答案"故障案例集 → **复用** 判定/③分析/异常联动诊断 跑一遍 → 评分：
  - 定位命中率 top-1 / top-3（AI 结论是否命中 ground truth）；
  - 误报率（无故障时是否误报）；
  - 报告质量（结构/证据充分，O4 校验辅助）；
- **对比**：模型 A/B · Skill/Prompt A-B · 有无记忆 · 雷达图/对比表；
- 测试集与结果落库（eval_case / eval_result），可回归。

### 7.3 安全（D39 + D48 横切）

- **威胁模型（对照真实场景）**：单管理员 + 全私网/隧道 + 自备 API key → 公网滥用威胁不存在，不设计；重点防 3 件。
- **3 件要防**：
  1. 间接/RAG 文档注入 → 系统指令与检索内容物理分隔 + 检索片段注入特征检测，可疑不给模型当指令；
  2. 敏感外泄 → 送 LLM 前脱敏（key/密码/路径替换）+ 输出敏感打码（D48 横切：所有生成文本落库/推前端前过一遍）+ API key 加密存 PG、不回显；
  3. 自身 Agent 失控循环 → LLM 限流器（信号量+令牌桶）+ 重试上限 + token 预算。
- **保留沿用**：直接输入注入检测 · admin 密码登录(JWT) · 执行安全四层(D30) · 审计。
- **审计横切（D48）**：对话/报告/诊断的工具调用+降级+注入拦截 → 统一审计日志（与 degradation_notes 呼应）。

### 7.4 异常联动 Executor 挂 D38 闭环

- 三图所有工具调用统一走 D38：入参自纠≤2 / 执行重试3退避(1s/2s/4s) / 三档降级 / degradation_notes 透明；
