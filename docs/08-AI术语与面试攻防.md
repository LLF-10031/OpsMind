## 一、核心 AI/Agent 术语词典

### RAG（Retrieval-Augmented Generation）
- **一句话**：生成前先从外部知识库检索相关文本，作为上下文喂给 LLM，减少幻觉、能溯源。
- **面试怎么说**："我用 RAG 让助手基于公司运维文档回答，检索走向量+BM25 RRF 融合，命中带引用、可跳原文，而不是模型凭记忆硬答。"
- **本项目**：结构化单元 + 多 key + parent_context；引用经校验管线核实（位置必须对）。

### ReAct / Function Calling
- **一句话**：Reasoning + Acting——模型 "思考→调用工具→看结果→再想" 的循环；Function Calling 是模型按声明好的工具签名输出 JSON 参数。
- **面试怎么说**："助手对未知信息不硬编，而是调 search_kb/read_run_output 等工具拿真实数据再回答；工具调用出入参均过 schema 校验（D38）。"

### Agent / 多 Agent 协作
- **一句话**：Agent=有工具+有状态+能多轮决策的 LLM 应用；多 Agent=多个子 Agent 分工协作。
- **面试怎么说**："我不会制造一堆 Agent 凑数——只有异常联动诊断是真多 Agent（Planner→并行 Executor→Reviewer），报告分析是确定性图+LV单 LLM，助手是单智能体+技能+工具。"
- **本项目（黑板协作）**：共享 DiagnosticState，各 Agent 只写自己格子，并行分工、上位汇总。

### MCP（Model Context Protocol）
- **一句话**：让 AI 应用标准化接入外部工具的协议（工具即服务，任何客户端按标准调用）。
- **面试怎么说**："目标机的脚本执行服务用 FastMCP 封装（ping/run_script/get_runtime_info），控制端经 SSH 隧道连——工具协议标准化，换 Java 实现也兼容（实习 ai-mcp-service 同协议）。"

### Skill / 渐进式披露（Progressive Disclosure）
- **一句话**：技能=可复用的"提示+工具子集"，按需加载而非全塞上下文。
- **面试怎么说**："系统提示只列技能清单(name+description)，用到时经 skill 工具取正文——省上下文，是 progressive disclosure。三个内置：system-health/log-root-cause/release-analysis。"

### 上下文压缩（Context Compaction）
- **一句话**：长对话把旧轮压缩成摘要、保留系统+最近轮，防止超上下文窗口。
- **面试怎么说**："compact 拆成 系统(恒定)+摘要+最近N轮+本轮；预算=ctx−max_output−reserved，80% 触发；摘要固定分区+增量，独立轻模型完成。"
- **关键点**：summary_cap=clamp(预算×20%,800,4000)；usage.prompt_tokens 每轮校准。

### 三层记忆
- **一句话**：Working(工作记忆/当前会话) + Episodic(情景记忆/历史事件) + Semantic(语义记忆/长期规律)。
- **面试怎么说**："Working 由压缩维护；Episodic 片段闭合沉淀历史；Semantic 让 LLM 从 ≥30 条史实提炼跨会话规律，带置信度衰减。注入用 query_memory 工具按需。"

### 向量检索 / Rerank / Embedding
- **一句话**：Embedding 把文本转为向量，向量检索找语义相似的；Rerank 对召回候选再排一遍提升精确度。
- **面试怎么说**："知识库向量化入 pgvector(text-embedding-v3)，+BM25 混合 RRF 融合，候选带 parent_context 给 LLM 选；rerank 作为演进点（单用户先省成本）。"

### 幻觉（Hallucination）与 Guardrails
- **一句话**：模型生成"貌似合理但不真实"的内容；Guardrails=输出前的校验护栏。
- **面试怎么说**："不靠提示词防幻觉，靠代码：O4 五阶段校验（结构/证据/矛盾/越界/等级一致）——每条结论必须挂真实引用，无引用强制标存疑，证据不足标'建议复核'。'
- **金句**："答案可以偏，位置必须对。"

### 提示词注入（Prompt Injection）
- **一句话**：恶意文本夹带"忽略以上指令…"，骗模型越权/泄密。
- **面试怎么说**："分直接(用户输入)和间接(文档/工具返回)两种都防：系统指令与检索内容物理分隔、检索片段注入特征检测、可疑不给模型当指令；输出侧敏感打码。"

### Plan-and-Execute / Planner-Executor-Replanner
- **一句话**：先定计划→执行步骤→执行中按结果重新规划。
- **面试怎么说**："异常联动诊断采用这个思路：Crit/error 才触发，Planner 拆假设(≤6)、Executor 并行查证真实数据、Reviewer 交叉验证——结论基于证据非编造，只花两跳主模型。'
>（本项目用 Planner→Executor→Reviewer，Replanner 未引入，简化且失控可控。）

### Agentic Workflow
- **一句话**：用工具调用+多步决策让 LLM 完成"需要行动"的任务（区别于一次问答）。
- **面试怎么说**："助手是 Agentic：可检索、可读报告、可触发巡查，都通过 ToolRegistry 白名单（只读优先、trigger 任务走 ask），受 D43 上下文预算管理。"

### Chain / StateGraph / LangGraph
- **一句话**：LangChain 是零件库（单次能力封装）；LangGraph 是有状态的多节点/分支/并行编排器。
- **面试怎么说**："单步调用用 LangChain 直接做；三张图（报告分析/异常联动/助手对话）用 LangGraph——多步骤、有分支、有状态才上图，不为图而图。"

### Structured Output
- **一句话**：模型按声明 schema 输出结构化 JSON，便于程序直接消费/校验。
- **面试怎么说**："判定让 LLM 输出 {level,reason}，工具出入参过 schema 校验（D38），报告/记忆都用结构化契约。"

### 置信度 / 衰减
- **一句话**：记忆/经验带置信度，随时间衰减，避免陈旧经验误导。
- **面试怎么说**："Semantic 经验带置信度，90 天半衰期衰减；同规律再出现则增强，防止过时经验坑人。"

### 令牌预算 / 限流 / 熔断
- **一句话**：控制 token 花费、约束调用频率、连续失败自动熔断降级。
- **面试怎么说**："所有 LLM 调用共用一个全局限流器(信号量+令牌桶)+优先级队列(诊断>③分析>摘要/记忆)；预算=ctx−max_output−reserved；工具失败走三档降级，均透明标注。"

## 二、Agent 专项攻防（先想后答）

### "你的 Agent 和直接调 LLM 有什么区别？"
> "它会'动手'：能检索、读报告、触发巡查，关键是这些动作经由 ToolRegistry 白名单与 D38 闭环（校验/重试/降级），且全程受 O4 校验与审计——不是一次问答，是有边界的工程决策循环。"

### "如何保证 Agent 不乱跑/不无限循环？"
> "单回合工具往返上限≤6（P-A）；上下文预算+限流器防失控；工具失败三档降级防卡死；运算超限标记 tool_call_invalid/tool_exec_error；诊断并发信号量≤2。"

### "记忆会不会污染/误用？"
> "前端可整体/分层开关+逐条删除/编辑；Episodic 走'代码硬杀+LLM判断+代码收尾'去重去杂；Semantic 必须跨≥2 会话+evidence 校验才入库，无规律不写。"

### "评估体系怎么做？（证明有用而非能用）"
> "离线注入'已知答案'故障案例集→复用判定/分析/诊断三图跑一遍→评分：定位命中率 top-1/3、误报率、报告质量；再跑模型 A/B、Skill/Prompt A-B、有无记忆对比，出雷达图。'
