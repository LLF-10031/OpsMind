## 一、Agent / LLM 应用八股

### 1. RAG 是什么？流程？
- **一句话**：先检索外部知识，再把检索结果作为上下文喂给 LLM 生成，减少幻觉、可溯源。
- **展开**：索引（分块→嵌入→入库）→ 检索（相似度）→ 生成（拼上下文）。难点在"检索准不准"。
- **本项目**：结构化单元 + 多 key，向量+中文 BM25 → RRF → topK → LLM 裁决；"勾选才查"。

### 2. 为什么 RAG 比微调更适合知识问答？
- **一句话**：知识更新频繁、要溯源、成本敏感 → RAG（改库即可、带引用）；微调适合"能力/风格"而非"频繁变动的事实"。

### 3. ReAct 与 Function Calling？
- **一句话**：ReAct="想→做→看结果→再想"的循环；Function Calling=模型按声明签名输出结构化调用参数。
- **本项目**：助手对未知信息不硬答，调 `search_kb/read_run_output` 等拿真实数据；工具出入参过 schema 校验（`tools` + D38）。

### 4. LangChain 与 LangGraph 区别？
- **一句话**：LangChain=零件库（模型/工具/检索器/嵌入），LangGraph=有状态的多节点/分支/并行编排器。
- **本项目**：单步调用用 LangChain；需要多步/有状态/分支的（报告分析、异常诊断、助手对话）用 LangGraph 思路；不自造框架。

### 5. 多 Agent 协作怎么做？黑板是什么？
- **一句话**：多个子 Agent 分工，通过**共享状态（黑板）**交换结果；每个只写自己那块，最后汇总。
- **本项目**：Planner→并行 Executor（日志/指标/变更）→Reviewer；`DiagnosticState` 里各写 `evidence.logs/metrics/changes`，Reviewer 汇总。

### 6. Agent 怎么防死循环 / 失控？
- **一句话**：工具往返上限 + 全局限流 + 超时 + 降级。
- **本项目**：单回合工具往返上限；全局限流器（信号量+令牌桶+熔断）；工具失败三档降级；诊断并发信号量。

### 7. MCP 是什么？和普通 API 有何不同？
- **一句话**：把"工具"按统一协议暴露，任何 AI 客户端按标准发现并调用；API 是给程序用的固定契约，MCP 是给"模型/Agent"用的可发现工具层。
- **本项目**：目标机 FastMCP 暴露 `ping/run_script/get_runtime_info`，控制端经隧道当 MCP client 调。

### 8. 上下文工程 / 上下文窗口？
- **一句话**：模型无状态，每次只看到你喂进去的 token；把"该给模型看什么"管好就是上下文工程。
- **本项目**：compact（系统+摘要+最近N+本轮）、按需注入（检索/记忆用工具而非全塞）、背景包。

### 9. Prompt Injection（提示词注入）分几种？怎么防？
- **一句话**：直接（用户输入）+ 间接（文档/工具返回夹带指令）。
- **本项目**：系统指令与检索内容**物理分隔**；检索片段注入特征检测；输出敏感打码；只读工具白名单。

### 10. 幻觉怎么治理？
- **一句话**：不靠提示词，靠"约束 + 校验 + 可溯源"。
- **本项目**：要求带引用锚点 → O4 校验（引用必须真实存在）→ 缺证据标存疑 → 出口打码/横幅；"答案可以偏，位置必须对"。

### 11. 评估怎么做（证明 Agent 有用）？
- **一句话**：造带 ground truth 的案例集，跑一遍打分。
- **本项目**：注入"已知答案"故障案例集 → 复用判定/分析/诊断 → 命中率 top-1/3、误报率、报告质量 + 模型/Skill/Prompt A-B + 雷达图。

### 12. Structured Output 为什么重要？
- **一句话**：让模型输出可直接被程序消费/校验的 JSON，而不是"话"。
- **本项目**：判定输出 `{level,reason,metrics}`；工具 schema；报告/记忆都用结构化契约。

### 13. Embedding / Rerank / 向量检索原理？
- **一句话**：Embedding 把文本映射成语义向量；向量检索按距离找近邻；Rerank 对候选再精排。
- **本项目**：`text-embedding`（可配，默认 DashScope 兼容）存 pgvector；rerank 作为演进点。

### 14. 温度 temperature / top_p / 上下文长度？
- **一句话**：temperature 控随机性（判定这类要稳定 → 低温度）；上下文长度=输入+输出总预算。
- **本项目**：判定要稳（低温度）；预算=窗口−输出−预留。

### 15. 微调 SFT / DPO 了解吗？
- **一句话**：SFT=用标注数据监督微调；DPO=用偏好对直接优化，不用强化学习奖励模型。
- **本项目**：未做微调（知识用 RAG、行为用 Prompt/校验解决）；若做评测驱动迭代，SFT/DPO 是演进方向（评测集已有基础：故障案例集）。

## 二、Python 八股

### 1. 同步/异步/协程，asyncio 怎么工作？
- **一句话**：事件循环单线程调度协程，`await` 遇 IO 让出控制权，实现高并发 IO。
- **本项目**：FastAPI 异步 + `async def` 路由/服务；MCP 调用、DB、LLM 都是 await；SSE 流式用异步生成器。

### 2. GIL 是什么？对并发有何影响？
- **一句话**：CPython 全局解释器锁，同一时刻一个线程执行字节码 → CPU 密集多线程无益、IO 密集可用。
- **本项目**：IO 密集走 asyncio；限流信号量用 `threading`（因为要跨事件循环/线程保护状态）。

### 3. asyncio、多线程、多进程怎么选？
- **一句话**：IO 密集→asyncio；CPU 密集→多进程；少量阻塞库→线程池 `to_thread`。
- **本项目**：主链路全异步；本地文件写、jieba 分词等同步操作直接小开销内联或 `to_thread`。

### 4. Pydantic 做什么？
- **一句话**：数据校验 + 序列化 + 类型转换；FastAPI 的请求/响应模型基础。
- **本项目**：模型/入参 schema 校验（工具契约 D38）、设置。

### 5. 依赖管理与包结构？
- **一句话**：`pyproject.toml` 声明依赖；`pip install -e .` 可编辑安装；包用 `app/` 分模块。
- **本项目**：`backend/pyproject.toml`（`[project]` + optional dev）；`app/{api,services,core,...}`。

### 6. 虚拟环境 / venv？
- **一句话**：隔离依赖，避免污染全局；`python -m venv .venv` + 激活。
- **本项目**：`backend/.venv`。

### 7. 生成器 / 迭代器 / async generator？
- **一句话**：惰性产出、省内存；async generator 支持异步惰性产出。
- **本项目**：SSE 事件流用 async generator/yield 逐步推送。

### 8. 装饰器 / 上下文管理器？
- **一句话**：装饰器=函数包装（如鉴权、限流）；上下文管理器=`with` 管理资源（开闭成对）。
- **本项目**：FastAPI 依赖注入做鉴权；`session_scope()` 管理 DB 会话。

### 9. 异常处理最佳实践？
- **一句话**：分层捕获、别裸 `except`、失败要有降级与记录。
- **本项目**：`core/exceptions.py` 分层异常；LLM/工具失败进 `degradation_notes`，不静默。

### 10. 类型注解与 typing？
- **一句话**：可读性 + IDE/静态检查；运行时默认不强制（Pydantic 会）。
- **本项目**：函数签名大量使用 `from __future__ import annotations` + 内建泛型。

### 11. 常见坑
- 异步里调用同步阻塞函数会卡事件循环 → 用 `to_thread`；
- `async` 函数忘记 `await` → 返回 coroutine 未执行；
- dict 可变默认参数 → 用 `field(default_factory=...)`（本项目 dataclass 已用）；
- 循环导入 → 用局部 import/注入（本项目多处 `from ... import` 放函数内）。
